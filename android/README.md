Technical documentation for the two Capacitor-based Android wrappers that ship the PRIVOX PTT web application as a native Android APK.

## 2. Build

### Requirements

| Tool | Minimum version | Notes |
|------|----------------|-------|
| Android Studio | Ladybug (2024.2) | ships JDK 21 (JBR) |
| JDK | 21 | use Android Studio's bundled JBR |
| Android SDK platform | API 36 | install via SDK Manager |
| Node.js / npm | any LTS | to run `npm install` in `android/` |

`local.properties` is **not committed** (gitignored). Create it in `phone/` and `t320/` before building:

```
# local.properties
sdk.dir=/Users/<you>/Library/Android/sdk
```

`org.gradle.java.home` can also be placed here if your system JDK is older than 21:

```
org.gradle.java.home=/Applications/Android Studio.app/Contents/jbr/Contents/Home
```

### First-time setup

```bash
cd android
npm install        # installs @capacitor/android into android/node_modules/
```

### Debug APK

```bash
# Phone
cd android/phone
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk

# Inrico T320
cd android/t320
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk
```

### Release APK (unsigned — for signing see below)

```bash
./gradlew assembleRelease
# → app/build/outputs/apk/release/app-release-unsigned.apk
```

### Install via ADB

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

### Clean build

```bash
./gradlew clean assembleDebug
```

### Updating web assets

Both apps load the web application **from a remote URL** (`https://ptt.privox.tech/…`). There are no bundled web assets — `assets/public/index.html` is a stub that is never shown. Deploying the web app on the server is sufficient to update what users see; no APK rebuild is required.

If the server URL changes, update `server.url` in `app/src/main/assets/capacitor.config.json` and rebuild.

### Changing versionCode / versionName

Edit `app/build.gradle` in the relevant project:

```groovy
defaultConfig {
    versionCode 5      // increment for every release uploaded to a store
    versionName "1.4"  // displayed to users
}
```

### Release signing

A signed release APK requires a keystore file. **Do not commit the keystore or its passwords.**

Required files (store locally, never in git):
- `app/my-release-key.keystore` — generate once with `keytool`
- `app/keystore.properties` — contains `storeFile`, `storePassword`, `keyAlias`, `keyPassword`

See `app/keystore.properties.example` (TODO: create this file) for the template.

Add to `app/build.gradle`:

```groovy
android {
    signingConfigs {
        release {
            def props = new Properties()
            props.load(new FileInputStream(rootProject.file("keystore.properties")))
            storeFile     file(props['storeFile'])
            storePassword props['storePassword']
            keyAlias      props['keyAlias']
            keyPassword   props['keyPassword']
        }
    }
    buildTypes {
        release { signingConfig signingConfigs.release }
    }
}
```

## 3. Phone build (`phone/`)

### WebView URL

```
https://ptt.privox.tech/app
```

The activity opens this URL on launch. No local bundle is served. The WebView renders the full React SPA.

### Permissions (`AndroidManifest.xml`)

| Permission | Purpose |
|-----------|---------|
| `INTERNET` | WebView network access |
| `ACCESS_NETWORK_STATE` | network-change detection |
| `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION` | geolocation (used by the web app for dispatcher map) |
| `RECORD_AUDIO` | PTT microphone |
| `MODIFY_AUDIO_SETTINGS` | audio mode control |
| `WAKE_LOCK` | `PARTIAL_WAKE_LOCK` in foreground service |
| `FOREGROUND_SERVICE` | running a foreground service |
| `FOREGROUND_SERVICE_MICROPHONE` | API 34+ type declaration for microphone service |
| `POST_NOTIFICATIONS` | foreground service notification (API 33+) |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | system dialog to whitelist the app |

### Foreground service (`PrivoxForegroundService`)

- **Type** declared in manifest: `microphone`  
  (chosen because `RECORD_AUDIO` is already held; `connectedDevice` type would additionally require Bluetooth/WiFi/NFC permissions which the phone build does not request)
- **Notification channel**: `privox_service`, `IMPORTANCE_LOW`, no badge, no sound
- **Notification**: "PRIVOX PTT — Connected — ready to receive", `ONGOING`, `VISIBILITY_PUBLIC`
- **START_STICKY** — OS restarts the service if it is killed

### WakeLock

`PowerManager.PARTIAL_WAKE_LOCK` tag `PrivoxPTT::ServiceWakeLock`  
Acquired in `onCreate()`, released in `onDestroy()`. Keeps the CPU awake so the foreground thread can run.

### Wi-Fi Lock

`WifiManager.WIFI_MODE_FULL_HIGH_PERF` tag `PrivoxPTT::WifiLock`  
Acquired alongside the WakeLock. Prevents the Wi-Fi radio from entering power-save mode, which would drop the TCP connection used by Socket.IO.  
Has no effect on mobile data (cellular modem is managed separately by the OS).

### Battery optimization exemption

`MainActivity.requestBatteryOptimizationExemption()` — called on first launch.  
Shows the system dialog (`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) so the user can whitelist the app, disabling Android's Doze restrictions for this package.

**On Xiaomi / HyperOS devices**, the standard exemption is insufficient. Users must additionally go to:  
**Settings → Apps → PRIVOX PTT → Battery → No restrictions**  
and disable all "Optimisation" toggles in that section.

### Behaviour when the screen is off

Current implementation:
1. User presses Home → activity moves to background; foreground service keeps running
2. PARTIAL_WAKE_LOCK keeps CPU awake
3. Wi-Fi Lock keeps the Wi-Fi radio active
4. `onPause()` and `onStop()` both call `webView.onResume()` + `webView.resumeTimers()` to counteract Capacitor's default suspension of the WebView

**Known limitation**: despite the above, the Socket.IO connection still drops on some devices (tested: Xiaomi Android 15) after ~2 minutes. Root cause: Chromium's background tab throttling suspends JavaScript execution inside the WebView independently of the Android WakeLock and the WebView Java methods. The Socket.IO heartbeat (`pingInterval` = 25 s) stops, the server times out and disconnects the client.

The foreground service remains alive and the notification stays visible; only the Socket.IO WebSocket inside the WebView drops.

**Implemented wake path**: FCM delivers native incoming-call notifications while
the WebView socket is suspended. The user answers the native call screen, then
the WebView opens the requested group and reconnects Socket.IO/WebRTC.

## 4. Inrico T320 build (`t320/`)

### Differences from the phone build

| Feature | Phone | T320 |
|---------|-------|------|
| Server URL | `/app` | `/radio` |
| User-Agent suffix | — | `PrivoxT320` |
| Foreground service type | `microphone` | `connectedDevice` |
| Hardware PTT button | — | keyCode 230 + 231 |
| Hardware Back button | system default | `window.__privoxRadioBack()` |
| Speakerphone forcing | — | every 1 500 ms |
| Screen-wake flags | — | `setShowWhenLocked`, `setTurnScreenOn`, `FLAG_DISMISS_KEYGUARD` |
| Battery exemption dialog | yes | no |
| POST_NOTIFICATIONS request | yes | no |
| Wi-Fi Lock | yes | no |

### User-Agent

`capacitor.config.json` sets `"appendUserAgent": "PrivoxT320"`.  
The web app reads `navigator.userAgent` to detect a T320 and render the compact radio UI (`isRadioDevice()` in `web/src/utils/device.ts`).

### Hardware PTT button — key codes

Determined by running `adb logcat` on-device and observing `dispatchKeyEvent` log output:

| Button | keyCode | Constant |
|--------|---------|----------|
| Orange PTT (side) | 230 | `KeyEvent.KEYCODE_TV_DATA_SERVICE` |
| Black button (adjacent to PTT) | 231 | `KeyEvent.KEYCODE_VOICE_ASSIST` |
| Centre D-pad | 23 | `KeyEvent.KEYCODE_DPAD_CENTER` (passed through, not intercepted) |

The device keylayout marks keyCode 231 as a wake key; keyCode 230 is **not** a wake key, so pressing the orange PTT while the screen is off does not wake the device.

### PTT → WebView event translation

`dispatchKeyEvent` intercepts both keyCode 230 and 231:

```
ACTION_DOWN (repeatCount == 0)  →  KeyboardEvent("keydown", key=" ", code="Space")
ACTION_UP                       →  KeyboardEvent("keyup",   key=" ", code="Space")
```

Events are dispatched on both `document` and `window` so the React hook that listens to `Space` picks them up without changes.  
Long-press auto-repeat events (`repeatCount > 0`) are intentionally dropped.

### Hardware Back button

`onBackPressed()` evaluates:

```javascript
(function(){
  try {
    return (window.__privoxRadioBack && window.__privoxRadioBack()) ? '1' : '0';
  } catch(e) { return '0'; }
})()
```

If the JS function returns `'1'` (web app handled navigation internally), nothing else happens.  
If it returns `'0'` (already at the top level), `moveTaskToBack(true)` backgrounds the app — the foreground service keeps it alive.

`window.__privoxRadioBack` is defined in the web app (exposed via `window.__privoxRadioBack = ...`).

### Speakerphone

Chrome WebView switches the audio mode to `MODE_IN_COMMUNICATION` during WebRTC sessions, which routes audio to the earpiece. For a radio, the speaker must always be used.

`MainActivity` starts a `Handler` loop (`keepSpeakerOn`, interval 1 500 ms) that calls `audioManager.setSpeakerphoneOn(true)` whenever it is `false`. The loop runs only while the activity is resumed (`onResume` / `onPause`).

### Screen-wake flags (T320 only)

```java
setShowWhenLocked(true)   // show over lock screen (API 27+)
setTurnScreenOn(true)     // turn screen on when activity resumes (API 27+)
FLAG_DISMISS_KEYGUARD     // bypass non-secure lock screen
FLAG_KEEP_SCREEN_ON       // prevent screen from turning off while activity is foreground
```

These allow the activity to appear on top of the lock screen when the black button (231) wakes the device.  
**The orange PTT (230) does not wake the device** because the T320 keylayout does not mark it as a wake key. Pressing the orange PTT while the screen is off has no effect.

### T320 permissions

Same as the phone build, **minus**:
- `POST_NOTIFICATIONS` — not requested (T320 runs older Android that doesn't enforce this)
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` — not requested
- `FOREGROUND_SERVICE_MICROPHONE` — not used; service type is `connectedDevice` instead

`FOREGROUND_SERVICE_CONNECTED_DEVICE` is declared instead of `FOREGROUND_SERVICE_MICROPHONE`.  
This works on the T320 (older Android / manufacturer ROM); on stock Android 14+ it would require an additional Bluetooth/WiFi permission.

## 5. Native ↔ WebView interaction

### JavaScript functions called by Android code

| Called from | Expression | Purpose |
|-------------|-----------|---------|
| `MainActivity.onBackPressed()` (T320) | `window.__privoxRadioBack()` | returns `true` if web handled Back navigation |

No other JS functions are called by Android code.  
There is no `addJavascriptInterface` bridge; Capacitor's own JS ↔ Native bridge is used for Capacitor plugins.

### Keyboard events injected into WebView

Only the T320 build injects synthetic events:

```javascript
new KeyboardEvent("keydown", { key:" ", code:"Space", keyCode:32, bubbles:true, cancelable:true })
new KeyboardEvent("keyup",   { key:" ", code:"Space", keyCode:32, bubbles:true, cancelable:true })
```

Dispatched on both `document` and `window` so the web app's `useEffect(() => { window.addEventListener('keydown', ...) })` receives them.

### Capacitor plugins

`PrivoxPushPlugin` is a local Capacitor plugin registered by `MainActivity`. It
exposes the FCM token and a pending answered call to the remote WebView. The
`capacitor-cordova-android-plugins` module remains the standard empty Cordova
shim.

### Session startup and restoration

1. `MainActivity.onCreate()` starts `PrivoxForegroundService` via `startForegroundService()`
2. The WebView loads the remote URL (`/app` or `/radio`)
3. The web app checks `localStorage` for a JWT refresh token and attempts silent re-login
4. If the token is valid, the user is redirected to the radio screen and Socket.IO connects automatically
5. If the token is expired, the login form is shown

There is no Android-side session management; the web app owns authentication state.

### Behaviour after returning from background

When the user presses Home and then returns to the app:
- The activity resumes (`onResume`); the WebView was never destroyed
- If the Socket.IO connection is still alive, the UI is immediately usable
- If the Socket.IO connection dropped while in background, the web app's Socket.IO client will attempt automatic reconnection (built-in `reconnection: true`); on reconnect the `handleSocketReconnect` handler re-emits `join-group` to rejoin the active channel

## 6. Background mechanisms

### Foreground service — `PrivoxForegroundService`

| Property | Value |
|----------|-------|
| Class | `tech.privox.ptt.PrivoxForegroundService` |
| Manifest type | `microphone` (phone), `connectedDevice` (T320) |
| Notification ID | 1001 |
| Notification channel ID | `privox_service` |
| Channel importance | `IMPORTANCE_LOW` (no sound, no pop-up) |
| `onStartCommand` return | `START_STICKY` |

**Starting the service**: `MainActivity.startPrivoxService()` calls `startForegroundService()` (API 26+) or `startService()` (older). The service immediately calls `startForeground()` in `onStartCommand()`.

**Stopping the service**: send `Intent` with action `tech.privox.ptt.STOP_SERVICE`. Not currently wired to any UI button. The service also stops if the app is explicitly removed from the recents list by the user on non-`START_STICKY` devices.

**Behaviour after phone reboot**: the service does **not** automatically restart after reboot. There is no `BOOT_COMPLETED` receiver. The user must open the app manually. This is a known limitation — a `RECEIVE_BOOT_COMPLETED` receiver is not yet implemented.

### WakeLocks held

| Lock | Tag | Held by |
|------|-----|---------|
| `PowerManager.PARTIAL_WAKE_LOCK` | `PrivoxPTT::ServiceWakeLock` | both phone and T320 |
| `WifiManager.WIFI_MODE_FULL_HIGH_PERF` | `PrivoxPTT::WifiLock` | phone only |

Both locks are acquired in `PrivoxForegroundService.onCreate()` and released in `onDestroy()`.

### What was tried to keep Socket.IO alive when the screen is off

| Attempt | Result |
|---------|--------|
| `PARTIAL_WAKE_LOCK` (CPU awake) | service stays alive ✅; Socket.IO still drops ❌ |
| `WIFI_MODE_FULL_HIGH_PERF` Wi-Fi Lock | Wi-Fi radio stays up ✅; Socket.IO still drops ❌ |
| `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` dialog | Doze mode disabled for app ✅; Socket.IO still drops ❌ |
| Manual Xiaomi battery settings (No restrictions + Pas d'optimisation) | reduced aggression ✅; Socket.IO still drops ❌ |
| `webView.resumeTimers()` after `onPause()` | does not affect Chromium's background tab throttling ❌ |
| `webView.onResume()` + `resumeTimers()` after both `onPause()` and `onStop()` | does not affect Chromium's background tab throttling ❌ |

### Why WebView still suspends JavaScript

Chromium (the engine inside Android System WebView) applies **background tab throttling** independently of the Android `WakeLock` API and independently of `WebView.pauseTimers()` / `WebView.onPause()`. When the app is not in the foreground, Chromium may freeze or heavily throttle JavaScript timers and network callbacks. The Socket.IO client's heartbeat (default `pingInterval` 25 s) stops responding, and the server disconnects the socket after `pingTimeout` (20 s).

There is no public Android API to disable this throttling from Java code. The standard industry solution is FCM (see Section 7).

## 7. FCM (Firebase Cloud Messaging)

### Current call flow

1. A user presses the blue call button for another subscriber.
2. The server sends the normal Socket.IO event and an FCM high-priority data message.
3. If the Android app is backgrounded, `PrivoxFirebaseMessagingService` shows a
   native incoming-call notification and full-screen call activity.
4. `PrivoxIncomingCallRinger` plays the system ringtone independently of the
   notification channel for up to 45 seconds.
5. The recipient chooses **Answer** or **Decline**.
6. Answer opens the WebView, selects the requested group, and reconnects
   Socket.IO/WebRTC. Normal group PTT then continues in the existing web client.
7. Decline stops the ringtone, clears the pending call, and closes the separate
   incoming-call task without opening the main app.

Version 1.5 also supports dispatcher **CALL GROUP** calls. The server creates an
individual tracked call for each group member. Native Answer/Decline actions
report their result directly to `/api/calls/respond`; the dispatcher sees
`ringing`, `answered`, `declined`, or `timeout`.

FCM is used for explicit user/group wake calls, not as an audio transport and
not for every PTT transmission.

### Android components

| Component | Purpose |
|------|-------|
| `PrivoxPushPlugin` | exposes the FCM token and pending call to the remote WebView |
| `PrivoxFirebaseMessagingService` | receives high-priority call messages |
| `PrivoxIncomingCallRinger` | plays/stops the native incoming-call ringtone |
| `IncomingCallActivity` | lock-screen Answer/Decline UI |
| `PrivoxCallActionReceiver` | handles Decline from the notification |
| `CallResponseReporter` | reports native Answer/Decline using the one-time call token |

`google-services.json` is installed locally in both `phone/app/` and `t320/app/`
and remains gitignored.

The server uses Firebase Admin through the Coolify environment variable:

```text
FIREBASE_SERVICE_ACCOUNT_JSON={"type":"service_account",...}
```

Keep the service-account JSON out of Git, APKs, Docker images, and web assets.
