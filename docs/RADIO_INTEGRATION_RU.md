# Интеграция радиосвязи (DMR) в PrivoxPTT — план на будущее

> Статус: видение/план, не реализовано. Зафиксировано 2026-06-12.
> Цель: дать связь там, где нет/не нужна сотовая (завод, удалёнка, объекты без покрытия),
> и подключить обычные рации в нашу систему как абонентов.

---

## 1. Зачем это нужно

Наша система — **PTT-поверх-IP**: ей нужна *какая-то* IP-сеть (WiFi/LAN/сотовая).
Сотовая — лишь один из транспортов, не требование. Но есть сценарии, где IP вообще нежелателен:

- **Завод / цех** — своя территория, нужна простая надёжная связь, сотовая избыточна.
- **Удалённые объекты** без покрытия.
- **Требование автономности** — связь должна работать при упавшей сети/сервере/интернете.

Там выигрывает **настоящее радио (RF)**: одна точка покрывает объект, пробивает бетон/металл,
не зависит от инфраструктуры. Наша система при этом становится **ядром/диспетчеризацией**
поверх радиокрая (через шлюз), а не несущей голоса.

---

## 2. Архитектура (ключевая идея)

DMR = **(А) радиоэфир** + **(Б) IP-ядро/управление**. Наш продукт закрывает (Б), а (А)
добавляется радиожелезом. Это та же абстракция, что уже есть для ESP32 (узел заходит в группу
через мост) — только узел теперь радиошлюз.

```
  DMR-рации )))RF(((  шлюз (радио+мини-ПК) ──IP──┐
                                                  ▼
  Web / ESP32 ──socket/UDP──────────────────►  НАШ СЕРВЕР (ядро)
                                                группы = talkgroups
                                                + AMBE↔Opus транскод
                                                + правила/инциденты/датчики
```

Голос DMR-рации ↔ рация идёт через эфир (надёжно, локально), а шлюз **бриджит** этот эфир
в наши группы. IP-абоненты (web/ESP32) и радиоабоненты оказываются **в одних talkgroups**.

---

## 3. Tier I vs Tier II — главное про лицензию

DMR по ETSI бывает 3 уровней; для нас актуальны два:

| | **Tier I (PMR446)** | **Tier II (лицензируемый)** |
|---|---|---|
| Разрешение на частоты | ❌ не нужно, купил и работай | ✅ нужно (заявка регулятору + сбор) |
| Диапазон | 446 МГц (безлицензионный) | проф. UHF 400–470 / VHF 136–174 МГц |
| Мощность | ≤ 0.5 Вт | десятки ватт (репитер) |
| Репитер | ❌ запрещён | ✅ да |
| Покрытие | сотни метров, 1 здание/двор | весь объект/площадка |
| Оформление | нет | недели–месяцы, бумаги |

**«Лицензируемый» = частоты регулирует государство** (в РФ — ГКРЧ/Роскомнадзор: разрешение
на использование радиочастот + регистрация РЭС; в ЕС — нац. регулятор; в США — FCC). Оформлением
обычно занимается поставщик раций / частотный консультант. Лицензия привязана к месту и частотам.

> ⚠️ Не путать с **радиолюбительской (ham)** связью — она ТОЖЕ требует лицензию/экзамен.
> PMR446 (Tier I) — единственный реально «без разрешений».

---

## 4. Аналог vs цифра — будут ли имена

Дешёвые рации 446 выглядят одинаково, но бывают двух видов:

- **Аналоговые PMR446** → ❌ нет Radio ID → система видит только «канал говорит/молчит», без имён.
- **Цифровые DMR446 / dPMR446** → ✅ несут **Radio ID** (кто) и **Talkgroup** (кому) в каждой передаче.

👉 Чтобы абоненты были с **именами и группами**, покупать только **цифровые DMR**, не аналог.
Маппинг: Radio ID → пользователь в нашей базе; Talkgroup → наша группа.

---

## 5. Что будет видно в нашей системе

| Возможность | Аналог | DMR (446 или Tier II) |
|---|---|---|
| Голос в наши группы | ✅ (через шлюз) | ✅ |
| Имя говорящего | ❌ (или PTT-ID через MDC-1200) | ✅ Radio ID → имя |
| Несколько групп | по каналам/субтонам | ✅ по talkgroups |
| «Говорит сейчас» (RX, зелёный пульс) | как факт на канале | ✅ с именем и группой |
| Онлайн/офлайн в покое, **янтарный** | ❌ | ⚠️ только при включённом **ARS**, иначе «last heard» |

**Важное ограничение:** рации не шлют heartbeat, как наши IP-устройства. Поэтому богатое
присутствие (живой онлайн-огонёк, янтарный «в другой группе» в покое) по радио недостижимо
без ARS (Automatic Registration Service, есть в MOTOTRBO). Это ограничение радио, не нашего софта.
Реально видим: **«говорит сейчас / последний раз слышали»** + имя + talkgroup.

## 6. Шлюз: сам делать или купить?

**Железо — НЕ с нуля.** Собирается из готовых модулей (это сборка/интеграция, не проектирование платы).
**Софт — да, наш bridge надо написать** (основная работа), опираясь на зрелый open-source.

### Состав пилотного шлюза (симплекс, под Tier I / небольшую зону)

| Компонент | Что | Ориентир. цена* |
|---|---|---|
| MMDVM-хотспот плата | MMDVM_HS_Hat / Jumbospot (RF-модем DMR) | $30–60 |
| Мини-ПК | Raspberry Pi 4 (или Zero 2 W) | $35–70 |
| Обвязка | SD-карта, корпус, антенна, БП | $25–40 |
| AMBE-транскод | DVSI ThumbDV / DVstick 30 (донгл) — **или** софт-транскод (бесплатно, юр. серо) | $100–130 / $0 |
| **Наш софт-bridge** | связка MMDVM/DVSwitch ↔ mediasoup (разработка) | разработка |
| **Итого железо пилота** | | **≈ $200–300** |

Open-source, на который опираемся (не пишем мост с нуля):
- **MMDVMHost** — управление MMDVM-модемом.
- **DVSwitch** (`Analog_Bridge` + `MMDVM_Bridge`) — мост «DMR ↔ PCM по UDP (USRP)».
- **HBlink3** — открытый DMR-мастер (HomeBrew) на Python, как референс для серверной части.

### Для продакшна (Tier II, покрытие площадки)
- Полноценный **дуплексный репитер** (или дуплексный MMDVM + 2 радио) вместо хотспота.
- Лицензия на частоты (см. §3).
- Тот же наш bridge — архитектура не меняется.

> Хотспот MMDVM по дальности ≈ Tier I (маломощный). Для реального покрытия — дуплексный репитер.

## 7. Примеры раций для покупки

> Цены ориентировочные (на ~2026, сильно зависят от региона/поставки; в РФ/СНГ с ввозом обычно выше).
> Перед покупкой под Tier I — **проверить сертификацию «license-free» в своей стране** и что модель **цифровая DMR**, а не аналог.

### Бюджетные (пилот / небольшое предприятие)
- **Baofeng DM-1801 / DM-1701** — DMR, ~$45–70. Самый дешёвый старт.
- **TYT MD-UV380 / MD-380** — DMR, ~$80–110. Популярные, много прошивок/доков.
- **Retevis RT3S / Ailunce HD1** — DMR, ~$80–130. Надёжнее бюджета.

### Профессиональные (Tier II, продакшн)
- **Motorola DP1400 / Mototrbo R2 / R7** — ~$150–400+.
- **Hytera BD505 / PD505** — ~$150–300.
- **Kenwood NX-1300** — ~$250–400.

> Для пилота достаточно **2–4 бюджетных DMR-раций + один пилотный шлюз** (§6).

## 8. Этапы

1. **Пилот (без лицензии).** 2–4 цифровые DMR446-рации + пилотный шлюз (MMDVM+Pi+AMBE).
   Проверить цепочку: рация → шлюз → наши группы → имена → «кто говорит» → диспетчер.
2. **Софт-bridge (MVP).** Маппинг Radio ID→user, Talkgroup→group, RX/«говорит сейчас», AMBE↔Opus.
3. **Продакшн Tier II.** Лицензия + дуплексный репитер, покрытие площадки, тот же bridge.
4. **Углубление.** ARS-присутствие (где доступно), эскалация инцидентов датчиков в talkgroup (TTS/текст),
   объединённые talkgroups (web + ESP32 + DMR в одной группе).

---

## 9. Что нужно разработать (наша часть)

- **Bridge-сервис**: MMDVM/DVSwitch ↔ mediasoup (PCM ↔ Opus), как «устройство-узел» в группе
  (аналогично UDP-мосту ESP32).
- **AMBE↔PCM** транскод: донгл (просто) или софт.
- **Маппинг**: Radio ID ↔ user, Talkgroup ↔ group; PTT/keyup ↔ захват канала (наш PTT-lock).
- **Presence-адаптер**: «говорит сейчас / last heard» в наш presence; ARS — опционально.
- (Позже) **эскалация датчиков в радио**: TTS-аннонс или DMR-текст в talkgroup (см. §10 ниже).

---

## 10. Открытые вопросы / риски

- **AMBE-лицензия** — кодек проприетарный; чисто = через железный донгл.
- **Регуляторка** — Tier II требует лицензию на частоты; Tier I ограничен мощностью/без репитера.
- **Presence по радио** — без ARS только «last heard», не живой онлайн (объективное ограничение).
- **Задержка/тайминги** — half-duplex, TDMA, бюджет задержки моста.
- **Покрытие Tier I** — 0.5 Вт без репитера; для большого объекта недостаточно.

---

## 11. Связка с датчиками (для полноты картины завода)

Датчики уже transport-agnostic (B8): «последняя миля» (WiFi/ESP-NOW/**LoRa**) отделена от
`POST /api/telemetry`. Для завода без сотовой:
- сетевые датчики → WiFi → локальный сервер;
- батарейные → **LoRa-мост** → локальный сервер (LoRa = «радио для датчиков», аналог DMR для голоса).

Один on-prem сервер = ядро и для **голоса (DMR/WiFi)**, и для **датчиков (LoRa/WiFi)**, с эскалацией
критичных инцидентов в голосовую группу. Подробности — в `docs/SENSORS_B8_PLAN_RU.md` и бэклоге (B9/B10).

## Короткий ответ на главные вопросы

- **Tier II лицензируемый** = нужна лицензия на **частоты** (зато репитер + покрытие).
- **Tier I (DMR446)** = **никаких разрешений, купил и подключил**; для небольшого предприятия хватает.
- Чтобы рации были «как обычные абоненты»: брать **цифровые DMR446** (не аналог) + поставить **один шлюз**.
- **Шлюз сам делать?** Железо — собрать из готовых модулей (~$200–300 пилот), плату не проектируем;
  софт-мост — написать (наша работа, на базе DVSwitch/MMDVM/HBlink3).
- **«Как PoC»**: по голосу/имени/«кто говорит» — да; живого присутствия в покое и покрытия
  дальше радиуса шлюза/репитера — нет (ограничения радио, не софта).
