# PRIVOX PTT — пробуждение Android-телефонов через FCM

## Задача

JavaScript внутри Android WebView при выключенном экране может быть
приостановлен Chromium. Из-за этого Socket.IO перестаёт отвечать на heartbeat,
сервер считает абонента отключённым, и обычный вызов через WebSocket до него не
доходит.

Foreground Service, CPU WakeLock, Wi-Fi Lock и исключение из оптимизации батареи
сохраняют Android-процесс, но не гарантируют выполнение JavaScript WebView.

## Реализованное решение

Для явного индивидуального вызова используется Firebase Cloud Messaging:

1. Android-приложение получает FCM-токен.
2. После входа WebView регистрирует токен через `POST /api/devices/register`.
3. Сервер хранит токен в таблице `Device`.
4. При `user-call-request` сервер:
   - отправляет обычное Socket.IO-событие, если адресат онлайн;
   - отправляет high-priority FCM data message на Android-устройства адресата.
5. Нативный `FirebaseMessagingService` принимает сообщение, даже если JavaScript
   WebView приостановлен.
6. Телефон включает экран, вибрирует, воспроизводит системный рингтон и показывает
   экран входящего вызова.
7. **ANSWER** открывает PRIVOX PTT, выбирает нужную группу и восстанавливает
   Socket.IO/WebRTC.
8. **DECLINE** останавливает рингтон, очищает вызов и закрывает отдельный экран,
   не открывая основное приложение.

FCM используется только как сигнал пробуждения. Голос через Firebase не
передаётся: после ответа связь продолжает работать через существующий
Socket.IO/WebRTC/MediaSoup контур.

## Статусы доступности

| Цвет | Состояние | Возможность вызова |
|---|---|---|
| Зелёный | Socket.IO активен, сервер получает heartbeat | Да, немедленно |
| Синий | Socket.IO отсутствует, но есть активный FCM-токен | Да, через push |
| Серый | Нет Socket.IO и активного FCM-токена | Нет |

Цвет применяется к точке, имени и телефонной иконке там, где это предусмотрено
интерфейсом. Телефонная иконка:

- зелёная — вызов онлайн-абонента;
- синяя — пробуждение спящего Android-абонента;
- серая — вызов недоступен.

### Почему станции меняют цвет не одновременно

- сервер ждёт истечения Socket.IO heartbeat/TTL;
- разные WebView засыпают с разной задержкой;
- экраны дополнительно обновляют данные периодическим API-запросом;
- локальный Service Worker может кратковременно показывать старую веб-сборку.

Обычная задержка между станциями может составлять 30–60 секунд.

## Android-компоненты

| Компонент | Назначение |
|---|---|
| `PrivoxPushPlugin` | FCM-токен и передача ожидающего вызова в WebView |
| `PrivoxFirebaseMessagingService` | приём high-priority FCM data message |
| `PrivoxIncomingCallRinger` | независимое воспроизведение рингтона до 45 секунд |
| `IncomingCallActivity` | отдельный lock-screen экран ANSWER/DECLINE |
| `PrivoxCallActionReceiver` | очистка вызова из системных действий |

Экран входящего вызова имеет отдельный Android task affinity. Поэтому DECLINE не
показывает лежавшее под ним основное приложение.

## Серверные компоненты

- Prisma-модель `Device`;
- миграция `20260606130000_add_push_devices`;
- API `/api/devices/register` и `/api/devices/unregister`;
- Firebase Admin SDK в `server/src/services/push.ts`;
- переменная Coolify `FIREBASE_SERVICE_ACCOUNT_JSON`;
- автоматическое отключение недействительных FCM-токенов.

Сервисный JSON Firebase нельзя хранить в Git, APK, Docker image или web assets.

## Что пока не реализовано

- кнопка «разбудить всю группу»;
- синхронный серверный статус `online/reachable/offline` для всех экранов;
- подтверждения caller-у: `ringing`, `answered`, `declined`, `timeout`;
- автоматическое обновление APK;
- автозапуск после перезагрузки Android;
- iOS/APNs-клиент.
