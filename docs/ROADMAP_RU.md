## Тир 1 — решает, нужен ли вообще следующий большой кусок работы

### 1.1. Решающий опыт: живёт ли уже ОТВЕЧЕННЫЙ звонок после сворачивания iPhone
Единственный вопрос, от которого зависит, нужна ли многонедельная работа
(нативный звук в обход WebView, Apple PushToTalk Framework) или тема закрыта.
Сформулирован ещё в `IOS_CALLKIT_RU.md` ("Решающий опыт"), ни разу не
поставлен за весь август — все тесты проверяли момент дозвона/разъединения,
не устойчивость уже идущего разговора в фоне.

**Как поставить:** ответить на звонок, свернуть приложение (не блокировать
экран, просто уйти на рабочий стол), подождать 30-60 секунд, вернуться —
разговор продолжается или прервался тишиной.

**Не начинать тир 2 (нативный звук) без этого ответа** — цена ошибки
слишком велика в обе стороны: если разговор живёт — фаза 2 не нужна вообще,
если нет — оценка 3-5 недель, отдельная архитектура.

### 1.2. iOS: маршрутизация звука (динамик/наушник) — сделано для Android, не для iOS
На Android уже разведены динамик для группы и наушник для личного звонка
(D16, нативный плагин `PrivoxAudio`). На iOS аналога нет вообще — сделать
через `AVAudioSession.overrideOutputAudioPort`, **платный аккаунт для этого
не нужен**, обычный нативный код. Независим от решающего опыта выше, можно
делать в любом порядке.

## Тир 2 — то, что реально ждут пользователи прямо сейчас

### 2.1. Полная публикация в App Store (после того как TestFlight обкатается)
Явное решение Eugene (26.08.2026): сначала полностью отладить через
TestFlight, потом публиковать. Когда возьмётесь — весь объём уже расписан
в D23 (`BACKLOG_RU.md`): скриншоты, описание, Privacy questionnaire
(отдельная детальная анкета, не просто `/privacy` URL, который уже готов),
демо-аккаунт для ревьюера, решение по имени разработчика (Individual на
Eugene vs Organization/PRIVOX — публично видно всем в сторе), риск отказа по
Guideline 4.2 (у нас уже есть весомый контраргумент — микрофон, CallKit,
PushKit, нативный аудио-роутинг).

**Условие готовности:** нет открытых регрессий из тира 1, TestFlight
поработал на реальных тестировщиках хотя бы неделю-две без новых находок.

### 2.2. Груповой "будильник" через CallKit — закрепить тестом
Работает по сообщению Eugene (26.08.2026), но без детального прогона с
логами, как у индивидуальных звонков. Разница в архитектуре: групповой
звонок — симплекс (D15 сознательно не даёт группе полный дуплекс), стоит
явно проверить, что ANSWER действительно ведёт в общий канал, а не путается
с одиночным дуплекс-путём.

### 2.3. D25 — перевыпуск приглашения по всему аккаунту, а не по одной группе
Найдено вживую 26.08.2026: `reissue` жёстко привязан к одной группе, хотя
человек может состоять в нескольких. Не блокирует ничего (пароль всегда
восстанавливает полный доступ), но неудобно как основной сценарий
"абонент переустановил телефон, у него несколько групп". Требует решения по
UX (что показывать на `/join/<токен>`, если групп несколько) — см. открытый
вопрос в самом D25.

## Тир 3 — большие блоки, которые пока не начинались

Эти три темы не связаны с телефонами/CallKit — отдельные, самостоятельные
фронты работы, каждый достаточно большой, чтобы быть отдельной веткой:

### 3.1. Датчики: единая система (B4, B6, B8, B9)
Сейчас метрики только temperature/humidity, у каждого датчика своя отдельная
панель (Frigo, HomeClimate). План уже есть в `SENSORS_RU.md` и
`SENSORS_B8_PLAN_RU.md`: универсальный протокол телеметрии, единый дашборд,
переход на LoRaWAN. Не начато. Имеет смысл начинать с B8 (унификация
протокола) — остальное на него опирается.

### 3.2. Мини-рации: качество звука (A1, A2)
Перегруз/искажения на обеих платах ESP32 мини-раций — открытый вопрос,
непонятно даже, где именно проблема (микрофон, усиление, DC-offset). Нужна
отдельная диагностическая сессия с осциллографом/анализом сырого сигнала,
не откладывать на потом бездумно — качество звука прямо влияет на то, можно
ли вообще предлагать эти рации всерьёз.

### 3.3. Радио: тревога датчика на T320/мини-рацию (C-SENSOR-ALARM, C7)
Рации сейчас вообще не получают тревоги датчиков — только веб-консоль и
push на смартфоны. Требует нового UDP-пакета тревоги от сервера и обработчика
в прошивке. Связано с C7 (все статусы на OLED) — разумно делать вместе.
