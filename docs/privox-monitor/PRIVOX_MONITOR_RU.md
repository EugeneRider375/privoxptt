# Privox Monitor — платформа мониторинга датчиков (задание на будущее)

> Статус: **идея / план**, не в работе. Создано 2026-06-13. Имя утверждено: **Privox Monitor**.
> Эта папка (`docs/privox-monitor/`) — дом для всей документации продукта.

## 1. Что это
Отдельный веб-продукт для клиентов, которым **не нужна диспетчерская связь (PTT)** — нужен только **мониторинг датчиков + оповещения**. Клиент видит на компьютере/телефоне состояние всех своих датчиков и получает алармы при нарушении заданных порогов. Универсальная мультиарендная платформа, а не одна вертикаль.

## 2. Вертикали (один код — много рынков)
Платформа обобщённая; «отрасль» — это набор пресетов датчиков и порогов:
- 🐄 **Ферма / животноводство** — температура коровника, движение (периметр), вода, влажность почвы, освещённость.
- 🅿️ **Парковки / шлагбаумы** — занятость мест, открытие/закрытие шлагбаума, движение, проезд.
- 🏠 **Дома / коттеджи / дачи** — охрана (движение, двери/окна), протечка, температура, дым.
- 🏪 **Супермаркеты (cold chain)** — температура холодильников/морозильных камер (контроль порчи), двери камер.
- 🌱 **Теплицы** — температура, влажность, освещённость, CO₂, полив.
- 📦 **Склады / серверные** — температура, влажность, протечка, движение, питание.

Ферма — первая вертикаль, но строить сразу под обобщение.

## 3. Ключевое архитектурное решение
**НЕ форкать.** Бэкенд общий с PrivoxPTT, для Monitor — отдельный лёгкий фронтенд на тот же API.

| Переиспользуем (готово) | Убираем | Добавляем |
|---|---|---|
| `/api/telemetry` (push-приём) | PTT / WebRTC / mediasoup | Отдельный фронт (бренд Privox Monitor, свой логин) |
| Модель Sensor + правила/пороги | Группы, диспетчер, рации | Telegram-бот для алармов |
| Инциденты (open/resolve, entry delay, авто-сброс) | Presence/звонки/сообщения | Пресеты типов датчиков по вертикалям |
| Мультиарендность (Organization) | — | Роль владельца аккаунта (OWNER) |
| FCM-пуши + PWA (ставится как app) | — | (опц.) свой мобильный апп — позже |

«Клиент/объект» = организация без PTT-юзеров. Личный кабинет = отдельная org + аккаунт владельца.

## 4. Что видит клиент (MVP)
- Дашборд всех датчиков: статус (OK/ALERT/STALE), последнее значение, батарея/связь, время отчёта, карта (lat/lng уже есть).
- Карточка датчика: история (графики), пороги, вкл/выкл сирены/уведомлений.
- Настройка датчика: выбор **типа/пресета** + ручная подстройка порогов.
- Лента инцидентов (что/когда сработало, когда отбой).

## 5. Типы датчиков и пресеты
Клиент выбирает тип — получает разумные дефолты, дальше правит: температура, влажность, уровень воды/протечка, движение (охрана: armed + entry delay уже есть), освещённость (lux), CO₂, влажность почвы, дверь/ворота/шлагбаум (открыто/закрыто), питание, здоровье устройства (батарея/связь).

## 6. Оповещения
1. **Telegram-бот (фаза 1)** — клиент привязывает chat_id/канал, туда летят алармы (порог, отбой, офлайн датчика). Минимум трения.
2. **PWA + FCM-пуш (уже есть)** — устанавливается как приложение, получает пуш.
3. **Свой мобильный апп — опционально, позже.**

## 7. LoRa (дорожная карта)
Push-модель совместима: LoRa-шлюз принимает пакеты датчиков → форвардит `POST /api/telemetry` по ключу. Дальние объекты без WiFi/сотовой. См. прошивки в `privox-sensors`.

## 8. Фазы
- **Ф0 (сейчас, попутно):** растим ядро — типы датчиков, прошивки (privox-sensors), LoRa, правила. К старту Monitor платформа почти готова.
- **Ф1 MVP:** отдельный фронт (дашборд + настройка), роль OWNER, Telegram-бот. Одна-две вертикали (ферма + cold chain).
- **Ф2:** графики/история, пресеты по вертикалям, карта объектов, PWA-онбординг.
- **Ф3:** самостоятельная регистрация, биллинг/тарифы, остальные вертикали (парковки, дома, склады, серверные).

## 9. Открытые вопросы
- Домен (monitor.privox.* ?).
- Отдельный фронт в монорепо vs отдельный репозиторий (рекомендация: монорепо, общий API-клиент).
- Регистрация: самостоятельная или завод аккаунтов вручную на старте.
- Биллинг/тарификация (потом).

## 10. Почему малорискованно
Тяжёлое (приём телеметрии, правила, инциденты, охрана, пуши, мультиарендность) **уже на проде**. Monitor — это в основном **новый фронтенд + Telegram-бот + роль OWNER + пресеты** поверх готового ядра.
